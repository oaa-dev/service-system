# ServiceOrder Module

## Model
- **Path**: app/Models/ServiceOrder.php
- **Table**: service_orders
- **Fillable**: merchant_id, service_id, customer_id, order_number, quantity, unit_label, unit_price, total_price, fee_rate, fee_amount, total_amount, status, notes, estimated_completion, received_at, completed_at, cancelled_at
- **Default attributes** (`$attributes`):
  - status -> 'pending'
  - fee_rate -> 0
  - fee_amount -> 0
  - total_amount -> 0
- **Casts**:
  - quantity -> decimal:2
  - unit_price -> decimal:2
  - total_price -> decimal:2
  - fee_rate -> decimal:2
  - fee_amount -> decimal:2
  - total_amount -> decimal:2
  - estimated_completion -> datetime
  - received_at -> datetime
  - completed_at -> datetime
  - cancelled_at -> datetime
- **Relationships**:
  - merchant -> BelongsTo -> Merchant
  - service -> BelongsTo -> Service
  - customer -> BelongsTo -> User (FK: customer_id)
- **Traits**: HasFactory
- **Scopes**: none

### Status Workflow
```
pending -> received -> processing -> ready -> delivering -> completed
    |           |                     |
cancelled   cancelled             completed
```
Valid transitions (defined as `VALID_TRANSITIONS` in `ServiceOrderService`):
| From | To |
|------|----|
| pending | received, cancelled |
| received | processing, cancelled |
| processing | ready |
| ready | completed, delivering |
| delivering | completed |

Timestamp fields set automatically on transition:
- `received_at` -- set when status becomes `received`
- `completed_at` -- set when status becomes `completed`
- `cancelled_at` -- set when status becomes `cancelled`

### Order Number Format
Auto-generated by `ServiceOrderService::generateOrderNumber()`: `ORD-YYYYMMDD-NNN` (e.g. `ORD-20260227-001`). Sequential per day; zero-padded to 3 digits.

### Pricing Fields
| Field | Description |
|-------|-------------|
| unit_price | Price of the service at time of order |
| quantity | Quantity ordered (decimal, e.g. 1.5 kg) |
| unit_label | Unit description (kg, pcs, gal, load) |
| total_price | unit_price x quantity (subtotal before fee) |
| fee_rate | Platform fee percentage (from PlatformFee config) |
| fee_amount | Calculated fee amount |
| total_amount | total_price + fee_amount (what customer pays) |

Gate: merchant must have `can_sell_products = true` to accept orders. Uses `sell_product` transaction type for platform fee lookup.

## Query Filters (index endpoint)
Allowed filters via Spatie QueryBuilder:
- `filter[status]` -- exact match
- `filter[service_id]` -- exact match
- `filter[customer_id]` -- exact match
- `filter[date_from]` -- created_at >= value
- `filter[date_to]` -- created_at <= value
- `filter[search]` -- order_number LIKE or customer name/email LIKE

Allowed sorts: id, order_number, status, total_price, created_at
Default sort: -created_at (descending)

## Customer Portal Query Filters (myOrders)
- `filter[status]` -- exact match
- `filter[date_from]` -- created_at >= value
- `filter[date_to]` -- created_at <= value
- `filter[search]` -- order_number partial match

Allowed sorts: created_at, status, order_number
Default sort: -created_at (descending)
Eager loads: service, service.media

## Notes
- `ServiceOrderService` injects both `MerchantRepositoryInterface` and `PlatformFeeServiceInterface`. Fee calculation happens at order creation time; the rate and amount are stored on the record.
- Branch merchants share services with their parent organization. During order creation, `$serviceMerchantId = $merchant->parent_id ?? $merchantId` is used to look up the service, ensuring branch orders reference parent-level services.
- The `ServiceOrderRepository` is registered in the service provider but not used by `ServiceOrderService` directly -- the service builds QueryBuilder queries directly on the `ServiceOrder` model.
- Customer portal cancellation (`cancelMyOrder`) scopes to `customer_id = auth()->id()` and allows cancelling only `pending` orders (stricter than booking/reservation which also allow cancelling confirmed).
- Permissions namespace: `service_orders.*` (note underscore).
- The `quantity` field is decimal (supports fractional quantities like 2.5 kg) with `unit_label` describing the unit of measurement.
- Note the difference in `unit_label` max length between admin request (max:20) and customer portal request (max:50).
- ServiceOrder is a `conversable` morph target (alias: `'service_order'`) in the Conversation system. Customers can chat with the merchant about an order via `GET/POST /api/v1/customer/my/conversations/orders/{id}/messages`. See `conversation.md`.
